## 1. Identity & Mood

A single-page scrollable campaign report — a **story told in data, not a dashboard**. Numbers are the protagonist, every section tells one story, restraint is the signature.

The AI decides accent hue, mode (light/dark), and Hero shader from the user's brief. Shader choice is flexible — any shader can fit any mood with the right color palette. The following are suggested defaults:

- Growth / sales / revenue / celebration → Light, hue 30–55, `GrainGradient`
- Tech / SaaS / precision / engineering / 仪表 → Dark, hue 240–270, `Dithering`
- Premium / ceremony / annual / theatrical → Dark, hue 35–50, `MeshGradient`
- Health / sustainability / organic → Light, hue 140–165, `GrainGradient`
- Generic / unclear → Light, hue 240, `GrainGradient`

## 2. Color System

Color space: OKLCH. One `--brand-hue` drives accent; neutral ground stays fixed.

### Token template

Generate ALL tokens below. The intermediate tokens (`--surface-l1/l2/l3`, `--foreground-2/3`, `--primary-hl`, `--primary-soft`, `--ember-wash`) create visual depth — never skip them.

```css
:root {
  --brand-hue: <H>;

  /* Ground */
  --background:    oklch(<bg_L> <bg_C> <neutralH>);
  --surface-l1:    var(--background);
  --surface-l2:    oklch(<bg_L±0.024> <bg_C> <neutralH>);
  --surface-l3:    oklch(<bg_L±0.050> <bg_C> <neutralH>);

  /* Ink */
  --foreground:    oklch(<fg_L> 0.005 <neutralH>);
  --foreground-2:  oklch(<fg2_L> 0.005 <neutralH>);
  --foreground-3:  oklch(<fg3_L> 0.005 <neutralH>);

  /* Accent */
  --primary:       oklch(<pri_L> <pri_C> var(--brand-hue));
  --primary-hl:    oklch(<pri_L+0.06> <pri_C-0.02> var(--brand-hue));
  --primary-soft:  oklch(<pri_L+0.14> <pri_C-0.06> var(--brand-hue));
  --ember-wash:    oklch(<pri_L> <pri_C> var(--brand-hue) / 0.12);

  /* Borders */
  --border:        oklch(<border_val>);
  --border-strong: oklch(<border_strong_val>);

  /* Chart ramp (single-hue, 5 steps decreasing L/C) */
  --chart-1: var(--primary);
  --chart-2: oklch(<s2_L> <s2_C> var(--brand-hue));
  --chart-3: oklch(<s3_L> <s3_C> var(--brand-hue));
  --chart-4: oklch(<s4_L> <s4_C> var(--brand-hue));
  --chart-5: oklch(<s5_L> <s5_C> var(--brand-hue));
  --chart-hover: oklch(<hover_val>);

  /* shadcn compat */
  --font-sans: 'Geist Variable', 'Noto Sans SC Variable', 'PingFang SC', sans-serif;
  --card: var(--background); --card-foreground: var(--foreground);
  --popover: var(--background); --popover-foreground: var(--foreground);
  --primary-foreground: oklch(<contrast> 0 0);
  --secondary: var(--surface-l2); --secondary-foreground: var(--foreground);
  --muted: var(--surface-l2); --muted-foreground: var(--foreground-3);
  --accent: var(--surface-l2); --accent-foreground: var(--foreground);
  --destructive: oklch(0.577 0.245 27.325);
  --input: var(--border); --ring: var(--primary); --radius: 0.625rem;
}
```

### Reference values

**Light mode:** bg 0.96–0.98 C 0.003 · surface-l2 = bg_L - 0.024 · surface-l3 = bg_L - 0.050 · fg 0.14–0.18 · fg-2 0.40–0.50 · fg-3 0.58–0.65 · primary 0.55–0.72 C 0.14–0.18 · primary-hl = pri_L + 0.06, C - 0.02 · border `oklch(0.22 0.005 H / 0.09)` · border-strong `/0.18`.

**Dark mode:** bg 0.09–0.14 C 0.004–0.015 · surface-l2 = bg_L + 0.025 · surface-l3 = bg_L + 0.065 · fg 0.93–0.96 · fg-2 0.75–0.82 · fg-3 0.55–0.62 · primary 0.62–0.72 C 0.16–0.18 · border `oklch(1 0 0 / 0.06)` · border-strong `/0.12`.

### Color rules

- Focal numbers use `--primary`. Unit suffixes and delta arrows use `--primary-hl`.
- Charts: single-hue ramp `--chart-1` → `--chart-5`. Never rainbow, Tailwind defaults, or library defaults.
- Every `<Bar>` must set `fill` explicitly — recharts defaults to black.
- 60-30-10: 60% background, 30% foreground+surfaces, 10% accent.
- No `#000000` or `#FFFFFF` literals — tokens only (hex allowed only inside shader `colors` prop since shaders don't parse oklch).
- `--ember-wash` radial gradient marks Hero focal area and Outro only.
- Depth from shader, type scale, composition, spacing — not shadow stacks or `backdrop-blur`.

## 3. Typography

### Font stacks (4 CSS vars in `:root`)

Defined in the token template above (§2). Tailwind v4 reads `--font-sans` for the `font-sans` utility class — if omitted, all text falls back to browser default.

- **Title / Display Number** → `font-sans` (Tailwind utility) — Hero title, section headings, focal numbers
- **Number (tabular)** → `'Geist Variable', sans-serif` + `font-feature-settings: "tnum","lnum"` — KPI figures, chart values
- **Body / CJK** → `'Noto Sans SC Variable', 'Geist Variable', 'PingFang SC', sans-serif` — Paragraphs, captions, labels
- **Mono** → `'Geist Mono Variable', ui-monospace, monospace` — Eyebrow, meta, chapter marker, code

### Weight

- `font-normal` (400): body, captions, descriptions, quotes
- `font-medium` (500): titles, Display Number, delta values, unit suffixes, chapter markers
- Never `font-semibold` (600) or above. Emphasis from scale and color only.

### Display Number anatomy

Figure at Display Number scale in `--primary`; unit suffix inline at Unit Suffix scale `--primary-hl`, baseline-aligned `gap-2`. Unit ≈ 28–30% of figure height. Parent `min-w-0`, number `whitespace-nowrap`.

Long numbers: ≤7 chars default / 8–11 drop one tier / ≥12 drop two tiers.

**Multi-metric font-size rule (critical for readability):** When multiple focal numbers appear side-by-side in a grid row, font-size MUST scale down by column count — numbers must never overlap or overflow their cell:

| Columns | Max number scale | Example |
|---|---|---|
| 1 (Hero focal) | Display Number `text-[64px] md:text-[96px] lg:text-[140px]` | Single anchor metric |
| 2 | Section Primary `text-[34px] md:text-[44px] lg:text-[56px]` | Comparison pair |
| 3–4 | Section Secondary `text-[26px] md:text-[32px] lg:text-[40px]` | KPI row |
| ≥5 | `text-[20px] md:text-[24px] lg:text-[32px]` | Dense cluster |

Each cell: `min-w-0` + number `whitespace-nowrap`. Grid must use sufficient `gap-4` or `gap-6` between cells. If number + unit still risks overflow at the given scale, drop one additional tier. **Overlapping or clipped numbers are never acceptable.**

OpenType: `font-feature-settings: "tnum", "lnum"` on all data numbers. CJK: `textWrap: "balance"` + `max-w-[52ch]`.

## 4. Spacing & Layout

Base unit: 8px. Section padding: `py-24 px-6` mobile → `py-40 px-16` desktop. Container: `max-w-5xl` centered.

Gap scale: `gap-1` tight · `gap-3` label+number · `gap-8` paragraph↔KPI · `gap-12` KPI↔chart.

Grid: `gap-2`, `items-baseline`, `min-w-0` on flex/grid children.

Breakpoints (mobile-first): base (<768px) single-col · md (≥768px) two-col · lg (≥1024px) full grid · xl (≥1440px) gutters absorb. `min-h-dvh` for full-height.

Radius: panels/charts `rounded-[2px]`–`rounded-[4px]` (sharp); cluster cards `rounded-[12px]`–`rounded-[16px]`. No `rounded-xl`/`rounded-2xl`/`rounded-3xl`/blob cards. Metric cluster cells use background color differentiation only — no border, no shadow, no outline.

One observation per viewport. Overflow: truncate, wrap, or scale to longest plausible value.

## 5. Surface & Material

- Ground: `var(--background)` flat. WebGL shader only in Hero section.
- Borders: `1px solid var(--border)` whisper · `var(--border-strong)` for structure. Prefer spacing over borders.
- Shadow: none default. Depth from border + one-step surface-l2 lift.
- Panels frame charts/tables/metric-clusters only — never wrap every section in identical panels.
- **Do NOT use shadcn `<Card>` component for metric cells or KPI clusters.** `Card` carries default border and shadow styles. Use plain `<div>` with `bg-[var(--surface-l2)]` + `rounded-[12px]` + `p-6` instead.
- Each section carries one distinct material logic (open field, annotation rail, panel, typographic field) — vary by archetype.
- Ember-wash: CSS `radial-gradient(ellipse 800px 600px at 50% 38%, var(--ember-wash), transparent 70%)` on Hero and Outro only, layer above shader, below text.

## 6. Motion

Engines: `motion/react` · `motion-plus/react` (AnimateNumber) · `@paper-design/shaders-react` (Hero shader).

```ts
const EASE = {
  out:    [0.18, 0.85, 0.22, 1],
  spring: [0.42, 0, 0.3, 1],
};
```

- Element entrance: 600–1000ms, y: 32–36px, `EASE.out`
- Number rolling: 1.6–2.2s, `type:"spring"`, bounce: 0
- Curve pathLength: 2.4–3.0s, `EASE.out`
- WebGL shader: continuous, viewport-paused, speed: 0.5–1.1

### Entrance rules

Hero: `animate=` with stagger (`staggerChildren: 0.12–0.14`). All other sections: `whileInView`.

**Every `whileInView` must include `viewport={{ once: true, margin: "0px 0px -10% 0px" }}`** — without `once: true`, elements reset to hidden on scroll-out and disappear.

```tsx
<motion.div
  initial={{ opacity: 0, y: 34 }}
  whileInView={{ opacity: 1, y: 0 }}
  viewport={{ once: true, margin: "0px 0px -10% 0px" }}
  transition={{ duration: 0.8, ease: EASE.out }}
/>
```

### What to animate

Only **granular decorative elements**: Hero text rows (stagger), individual KPI cells, chapter opener text, outro flourish. One focal motion per archetype:

- Hero: staged reveal + number roll
- Time Series: area path draw (`pathLength: 0→1`)
- Proportion: rail fill
- Ranking: row cascade (staggered y)
- Quote: crossfade
- Outro: signature stroke reveal

Section shells, body paragraphs, chart wrappers, and prose render visible on first paint — never animated.

### What NOT to animate

- Never wrap `<section>` in `motion.div` with `initial={{ opacity: 0 }}` — causes disappearance on fast scroll
- Never animate layout props (`width`, `height`, `padding`, `margin`, `gap`)
- Never use `useScroll` / `useTransform` / `scrollYProgress`
- Never use ScrambleText / Typewriter / character-level reveal
- Never animate bar chart bars rising from zero — render bars static
- Never use `useInView()` + conditional `animate` for entrance — use `whileInView` + `viewport`

### AnimateNumber scope

Wrap **key numbers** only: Hero primary, section focal claims, Comparison left/right, Ranking top-1. Cap ≤ 3 per section. Never wrap labels, ordinals, dates, axis values. `AnimateNumber` children = pure numeric string — always `parseDisplayValue()` first (§8).

## 7. Section Design System

### 7.1 Process

1. **Identify data shape** → archetype
2. **Choose composition treatment** → layout structure
3. **Choose dominant move** → what leads the eye
4. **Verify rhythm** → no two consecutive sections share density, layout, or archetype

### 7.2 Composition Treatments

- **Full-bleed Monolith** — One element fills frame, vertically centered (spacious)
- **Asymmetric Split** — Two unequal columns (3:2 or 2:1), one leads (medium)
- **Stacked Band** — Full-width horizontal bands stacked vertically (medium–dense)
- **Matrix Grid** — Equal cells N×M, narratively bound to one claim (dense)
- **Proportion Rail** — Continuous rail carrying parts-of-whole (medium)
- **Typographic Field** — Type alone, no panels or chrome (spacious–medium)

### 7.3 Dominant Moves

- **Scale jump** — focal ≥ 2 tiers larger than surroundings (steady)
- **Single stroke** — one drawn line, accent stroke, or light cone (steady)
- **Path reveal** — curve draws in, rail fills (steady)
- **Crop / bleed** — focal cropped by edge or overflows frame (disruptive)
- **Offset placement** — focal deliberately off regular grid (disruptive)

Lead with scale jump and single stroke by default.

### 7.4 Archetypes

**Hero Monolith** — Opening anchor metric. Full viewport height (`min-h-dvh`). Treatments: Asymmetric Split **(default)** · Full-bleed Monolith · Typographic Field. Dominant: scale jump, single stroke. Slots: eyebrow · hero-title · subtitle · primary-value · unit · delta · metadata-aside.

**Time Series** — Values over time. Treatments: Stacked Band **(default)** · Asymmetric Split (chart leads, annotation on side). Move: path reveal. Build with shadcn `ChartContainer` + recharts `AreaChart`/`LineChart`.

**Proportion Field** — Parts-of-whole. Treatments: Proportion Rail **(default)** · Stacked Band. Move: path reveal, scale jump. No donut/pie/ring — read as horizontal rail or stacked bar with integrated labels.

**Comparison** — Two metrics contrasted. Treatments: Asymmetric Split **(default)** · Stacked Band. Move: scale jump. Same font-size for both; hierarchy from color — leading `--primary`, trailing `--foreground-3`.

**Ranking / List** — Items by magnitude. Stacked Band (≤5) · Matrix Grid (≥6, truncated). Move: scale jump on top-1. Row stack with emphasis — never recharts BarChart for ranking.

**Grouped Metric Cluster** — Parallel metrics evidencing one claim. Matrix Grid **(default)** · Stacked Band. CSS grid `gap-4`, cells `bg-[var(--surface-l2)]` `rounded-[12px]` `p-6 md:p-8`, each: label + focal number + optional note. Cells differentiate by background only — **no border, no shadow, no outline, no ring**. Number font-size follows §3 Multi-metric rule (3–4 cols → Section Secondary scale). Each cell `min-w-0`, numbers `whitespace-nowrap`. One claim's evidence, not a dashboard tile stack.

**Quote Interstitial** — Narrative pause. Typographic Field. One sentence ≤ 28 words. No italic, no left-border. Optional decorative L-shape brackets `--primary` at 0.6 opacity.

**Outro Reverent** — End reflection. Typographic Field · Full-bleed Monolith. Closing title + `OutroSignature` flourish + caveats. Optional — only when data supports a closing claim.

### 7.5 Rhythm Rules

1. **Density rotation** — adjacent sections differ in density (dense/medium/spacious)
2. **Treatment variety** — no two consecutive same layout or archetype
3. **Bold-move budget** — disruptive ≤ ceil(N × 0.25)
4. **Break cadence** — ≥ 1 section uses Full-bleed or Typographic Field per page

Skip sections whose data is absent — never pad with filler. Section count follows data richness (sparse: Hero + 1–2 chapters; rich: Hero + 5–7 chapters).

## 8. Hero

### Primary-value selection (priority order)

1. Rate/percentage field (`达成率`, `完成率`, `%`, `rate`) → average
2. Aggregate keyword (`总计`, `总数`, `合计`, `total`) → sum
3. Primary metric by semantics (revenue, GMV, sales, score) → max
4. Same field → average

If null/missing, omit Hero entirely.

### Composition

Hero section MUST be full viewport height: `min-h-dvh` on the `<section>`. Content vertically centered with `flex flex-col justify-center`.

**Design intent:** Hero is the user's first impression — a confident opening that communicates the report's core claim at a glance. It should feel like a magazine cover, not a dashboard header. Adapt the layout to serve the user's query: if the user mentions images/photos/精品图片/商品图/产品图, the Hero MUST prominently feature those images; if the user's brief is purely data-driven, lead with the focal number.

**Structure slots** (compose freely based on user intent):
- **Eyebrow**: `{topic} · {period}`, Meta mono `tracking-[0.16em]`, `--foreground-2`
- **Hero title**: Hero Title scale, `font-medium`, `--foreground`, `max-w-[20ch]`
- **Subtitle**: Lead Paragraph, `font-normal`, `--foreground-3`, `max-w-[52ch]`
- **Focal number block**: Display Number `--primary` + unit `--primary-hl` + DeltaIndicator
- **Visual region** (when user requests images): product images, feature photos, or hero artwork from Bitable attachment/URL fields — `object-cover`, `rounded-[4px]`, occupying 40–50% width on lg
- **Metadata aside** (optional, lg only): mono uppercase labels `--foreground-3` + values `--foreground`

**Layout adaptation rules:**
1. User mentions images/photos/图片/商品图/产品图/封面 → Asymmetric Split with image region (grid of 1–4 images on the right or bottom on mobile). Images MUST appear — never ignore user-requested visuals.
2. Data-heavy brief, no images → Asymmetric Split with focal number leading left, metadata aside right.
3. Minimal data, ceremonial tone → Full-bleed Monolith or Typographic Field.

**Critical:** The code example below is ONE possible layout. Do NOT copy it verbatim when the user's query calls for something different (e.g. images, different arrangement). Treat it as a reference for animation patterns and token usage only.

### Shader examples

4 shaders available from `@paper-design/shaders-react`. Choose based on the visual mood the report needs — colors are fully customizable, so any shader can serve light or dark mode with the right palette.

- **GrainGradient** — Multi-color gradient with grainy noise-textured distortion. 7 animated shape modes (`wave`, `dots`, `truchet`, `corners`, `ripple`, `blob`, `sphere`). Soft, organic feel. Works well for warm/celebratory, fresh/organic, or any tone where you want fluid color movement with subtle texture.
- **MeshGradient** — Flowing composition of color spots moving along distinct trajectories with organic distortion + optional vortex swirl. Rich, layered depth. Works well for premium/ceremonial, theatrical, or any tone wanting painterly motion.
- **Dithering** — 2-color dithering over animated pattern sources (`simplex`, `warp`, `dots`, `wave`, `ripple`, `swirl`, `sphere`). Retro-digital, pixel-precise aesthetic. Works well for tech/engineering, data-driven, or any tone wanting calculated precision.
- **GodRays** — Animated rays of light radiating from center with bloom and central glow. Dramatic, volumetric. Works well for dramatic reveals, energy/impact, or ceremonial spotlight moments.

## 9. Components

### parseDisplayValue + AnimateNumber

```tsx
import { AnimateNumber } from "motion-plus/react";

function parseDisplayValue(value: string | number | undefined) {
  if (value == null) return { prefix: "", number: "0", suffix: "" };
  const str = String(value);
  const match = str.match(/^([^\d\-]*?)(-?[\d,]+\.?\d*)(.*)$/);
  if (!match) return { prefix: "", number: "0", suffix: "" };
  return { prefix: (match[1]??"").trim(), number: match[2].replace(/,/g,""), suffix: (match[3]??"").trim() };
}

// "¥1,234,567.00" → prefix="¥", number="1234567.00", suffix=""
// "85%" → prefix="", number="85", suffix="%"
const { prefix, number, suffix } = parseDisplayValue(raw);

<span className="inline-flex items-baseline gap-1 whitespace-nowrap">
  {prefix && <span style={{ color:"var(--primary-hl)" }}>{prefix}</span>}
  <AnimateNumber
    style={{ color:"var(--primary)", fontFeatureSettings:'"tnum","lnum"' }}
    transition={{ type:"spring", duration:2.0, bounce:0 }}
  >{number || 0}</AnimateNumber>
  {suffix && <span style={{ color:"var(--primary-hl)" }}>{suffix}</span>}
</span>
```

### DeltaIndicator

```tsx
function DeltaIndicator({ value, direction }: { value: string; direction: "up"|"down" }) {
  const up = direction === "up";
  const color = up ? "var(--primary)" : "var(--foreground-3)";
  return (
    <span className="inline-flex items-center gap-1 text-[13px] font-medium whitespace-nowrap">
      <span style={{ color }} aria-hidden>{up ? "▲" : "▼"}</span>
      <span style={{ color }}>{value}</span>
    </span>
  );
}
```

### SpotlightGradient (dark mode ambient light)

```tsx
function SpotlightGradient({ position, intensity=0.7 }: { position:"top-center"|"top-right"|"bottom-center"; intensity?:number }) {

      content={<ChartTooltipCard/>} wrapperStyle={{ outline:"none" }} />
  </AreaChart>
</ChartContainer>
```

**Chart rules:**

1. **Every chart MUST be wrapped in `<ChartContainer config={...}>`** — never bare `<AreaChart>`/`<BarChart>`/`<LineChart>`. Without it, recharts has no `ResponsiveContainer` and the chart will not render.
2. **Use recharts `<Tooltip>` with `content={<ChartTooltipCard/>}`** — never use shadcn `<ChartTooltip>` or `<ChartTooltipContent>` (their default border/shadow cannot be reliably overridden). Always add `wrapperStyle={{ outline:"none" }}`.
3. `isAnimationActive={false}` on every recharts element.
4. Colors via `var(--color-{configKey})` or `var(--chart-N)`. Every `<Bar>` must have explicit `fill`. Never rainbow or library defaults.
5. BarChart cursor: `cursor={{ fill:"var(--surface-l3)", opacity:0.5 }}` (highlight background on hover).
6. AreaChart/LineChart cursor: `cursor={{ stroke:"var(--primary)", strokeDasharray:"2 4", strokeOpacity:0.5 }}`.

## 10. Voice & Copy

Reads like a curator's wall text — terse, third-person, observational.

- Statements, not CTAs: `Bookings closed at 142,300` not `We booked 142,300!`
- Chapter titles: sentence case, no period, 5–14 CJK / 4–9 EN words, names the outcome
- Eyebrows: uppercase mono `tracking-[0.14em]`; period format: `Q1 · 2026` (middle dot)
- Never: emoji, CTA buttons, "view more", dashboard verbs (track, monitor, drill down), marketing verbs (unlock, discover, supercharge), second-person imperatives

## 11. Do's and Don'ts

Do:
- Ground 60% viewport; accent 8–15%; ink the rest
- Focal numerals `--primary`; units/delta `--primary-hl`
- Single-hue chart ramp; latest period = chart-1
- One structural visual decision per viewport beyond color
- Alternate archetypes and density between adjacent sections
- Each section: one focal claim, one supporting visual

Don't:
- **Don't** use Display Number scale for multi-column KPI grids — numbers overlap and become unreadable. Follow §3 Multi-metric font-size rule strictly
- **Don't** add borders, outlines, or ring to metric/KPI cards — differentiate with background color only
- **Don't** use shadcn `<Card>` for metric cells — it carries default border/shadow. Use plain `<div>` with utility classes
- **Don't** render charts without `<ChartContainer>` — bare recharts components won't render. Never use shadcn `<ChartTooltipContent>` — use custom `ChartTooltipCard` only
- **Don't** use shadows, frosted glass, `backdrop-blur`, rim lighting, card-edge glow, text glow
- **Don't** nest panels beyond one level or wrap every section in identical material
- **Don't** use weight ≥ 600 or italic/serif
- **Don't** use `h-screen` (use `min-h-dvh`); no text below `text-[10px]`
- **Don't** render Hero without full viewport height — always `min-h-dvh`
- **Don't** use donut/pie/ring charts — proportion is rail or bar
- **Don't** use ease strings — cubic-bezier arrays only
- **Don't** wrap `<section>` in `motion.div` with `initial={{ opacity:0 }}`
- **Don't** animate bar chart bars rising from zero
- **Don't** use `useScroll`/`useTransform`/`scrollYProgress`
- **Don't** use emoji; no CTA/action buttons; no "view more" links
- **Don't** show archetype names in visible UI
- **Don't** force outro without closing claim; don't pad with filler sections
- **Don't** show >5 ranking items without truncation

## 12. Technical Constraints

- `isAnimationActive={false}` on every Recharts element
- No `#000000`/`#FFFFFF` — tokens only (hex allowed only in shader `colors` prop)
- `aria-hidden="true"` on decorative elements
- `lucide-react` for icons, 1–1.5px stroke, `currentColor`
- Continuous motion (shader, SVG loops) pauses off-viewport
- Null/undefined data → skip section entirely (never broken animation)
- App root: direct children of root `<div>` — no `<main>`/`<article>` wrapper (avoids stacking context conflicts with absolute shaders)
