Color rules:
- Focal numbers use `--foreground` (white). `--primary` (electric blue) is signal accent only: unit text, directional arrows, structural light, chart-1, delta-up state, and one accent element per section. Example: `48.9%` renders white digits `48.9` with the `%` sign in `--primary`.
- Charts use the ordered Primary blue ramp: chart-1 starts at `--primary`, chart-2 through chart-5 step darker in the same hue. No green, orange, rainbow, library-default categorical palette, or Tailwind palette.
- Single-series charts use chart-1 for the active line and chart-5 at low opacity for baselines, grids, and historical context.
- Chart hover cursor, active bar background, and tooltip highlight use `--chart-hover`, one step above background. Never use default white, light gray, or high-contrast hover bands.
- Depth comes from linework, spacing, typography, and restrained structural light; not shadow-heavy cards.
- No `#000000`. No `#FFFFFF`. Use defined tokens only.
- 60-30-10: 60% background, 30% surface+text, 10% accent.

Brand hue: `--brand-hue` is the only configurable accent knob. `--primary`, `--primary-hl`, `--primary-glow`, and `--chart-2` through `--chart-5` keep fixed lightness/chroma and take only hue from `--brand-hue`; `--chart-1` mirrors `--primary`. Neutral tokens — backgrounds, surfaces, foregrounds, borders, `--chart-hover`, `--quote-bg`, `--outro-bg`, `--glow-ink` — stay fixed.

## 4. Spacing & Layout

Base unit: Tailwind spacing `2` (8px). Scale: `1` `2` `3` `4` `6` `8` `12` `16` `24` (`1` = 4px).

Section padding: `py-24 px-6` mobile → `py-40 px-16` desktop. Container: `max-w-5xl` centered. Grid: `gap-2`, `items-baseline` for mixed text, `min-w-0` on nested flex/grid children.

Overflow: long numbers and labels never overlap or break the section frame. Truncate, wrap, or scale to the longest plausible value, not a short sample.

Density: one data story per viewport height. Gaps: `gap-1` tight internals · `gap-3` label+number · `gap-6` intra-section · section-level via padding.

Radius: `rounded-[0px]` sharp · `rounded-[2px]` standard · `rounded-[4px]` max for cards, panels, charts, tables, frames, and inline indicators. No `rounded-xl`, `rounded-2xl`, `rounded-3xl`, pill radius, blob card, or fully rounded card shape. Exception: tags and badges use full border-radius.

## 5. Material

Surface: elevated through thin border + near-black surface contrast. Panels use one-step lift (`--surface-l2` on `--background`), not stacked dark-on-dark.

Borders: Whisper `1px solid oklch(1 0 0 / 0.06)` · Strong `1px solid oklch(1 0 0 / 0.12)`. Shadow: `inset 0 1px 0 oklch(1 0 0 / 0.03)` only.

Noise texture: near-invisible overlay for tactile depth, opacity ≤ 0.12, overlay blend mode.

Structural light: cold radial glow from corners or horizon; electric blue light as material, never card-edge glow or text effect.

Outlined pill: low-opacity accent `1px solid` border, transparent background, full border-radius.

Dividers: accent `linear-gradient(to right, transparent, oklch(0.700 0.160 var(--brand-hue) / 0.3), transparent) h-px`; content `oklch(1 0 0 / 0.08) h-px`.

Panel discipline: panels frame charts, dense tables, or grouped evidence only; use sharp corners (`rounded-[2px]`) and thin borders. Each archetype carries one distinct material or spatial logic: instrument gauge, data rail, annotation margin, typographic field, or open negative space.

## 6. Motion

Engines: `motion/react` · `motion-plus/react` (AnimateNumber) · `@paper-design/shaders-react` (GodRays).

```ts
const EASE = {
  out:    [0.08, 0.95, 0.15, 1],
  inOut:  [0.86, 0, 0.10, 1],
  snap:   [0.12, 0, 0, 1],
  spring: [0.38, 0, 0.58, 1],
};
```

| Category | Duration | Easing |
|----------|----------|--------|
| Hover | 150ms | out |
| Button press | 100ms | snap |
| Element entrance | 500-900ms | out |
| Number rolling | 0.8-2.0s | spring physics, no visible bounce |
| Curve pathLength | 2.0-2.8s | out |
| Spotlight drift | 6s/cycle | inOut, infinite |
| WebGL | continuous | speed: 0.8 |

Entrance: Hero uses `animate=` with orchestrated delays. Other sections use `whileInView`, `once: true`, `margin: "-20%"`, and animate only the focal element. Section shell, headings, and readable text render visible before in-view animation.

Scroll-triggered entrance uses `whileInView` + `viewport`, not manual refs, `useInView`, and conditional `animate`.

```tsx
<motion.div
  initial={{ opacity: 0, x: -20 }}
  whileInView={{ opacity: 1, x: 0 }}
  viewport={{ once: true, margin: "-20%" }}
  transition={{ duration: 0.7, ease: EASE.out, delay: 0.2 }}
/>
```

Motion idea per viewport: one focal motion only. Hero staged reveal; Time Series path/fill draws; Proportion rail fills; Ranking rows cascade; Quote crossfades; Outro settles. Avoid the same `y + opacity` reveal for every section.

AnimateNumber: per-digit scroll triggers on child value change — always use `{displayValue || 0}` (see §17). **Scope rule** — wrap **every key number**: Hero primary metric (required), each section's focal claim, Comparison left/right values, Ranking top-1, Grouped Metric Cluster cell headlines, Sequence/Timeline milestone values, Peer Set featured value, and any number that carries a section's claim or primary evidence. Do **not** wrap labels, ordinals (rank 1/2/3), dates, axis values, footnote figures, or supporting sub-metrics that don't headline. **Soft cap**: ≤ 3 rolling numbers per section — past that the section becomes a dashboard tile stack; split the claims across sub-sections. Motion: spring, no bounce, per-digit column. Unit text stays outside the animated number and is never duplicated.

SVG: `pathLength: 0→1` draw-in. Breathing via `d` morph. No `<circle>` inside `preserveAspectRatio="none"`; use HTML border-radius.

`prefers-reduced-motion`: CSS `animation-duration: 0.01ms !important`; Motion opacity crossfade only; WebGL `speed: 0`; AnimateNumber plain final text.

Data-driven value invariant: numerical animation primitives need a meaningful value at each frame. When the data source returns null, undefined, or no rows, render the section's empty state (per §15) instead of attaching a broken animation.

Continuous motion: WebGL, SVG loops, CSS spotlight drift, and repeated background motion run only while their section is in view. Off-screen continuous motion pauses.

## 7. Iconography

`lucide-react`, 1–1.25px stroke, outline-only, `currentColor`. Sizing in rem, `gap-2` to text. Icons are never larger than the cap-height of the type they sit beside. Decorative: `aria-hidden="true"`. Semantic: `role="img"` + `aria-label`.

**Don't hand-draw SVG for icons.** Symbolic marks — quote glyphs, arrows, stars, info, warning, badges, ornaments — use `lucide-react` components (`<Quote />`, `<ArrowUp />`, `<Star />`, etc.). Custom SVG is reserved for: structural ornaments with bespoke geometry (ChapterStamp number badge), `motion.path` animated structural lines (§13.1 Hero), noise filter overlays (§17), and chart implementations (recharts internals). Unicode directional and separator characters (↑ ↓ · — •) are allowed for inline use.

## 9. Do's and Don'ts

Do:
- White focal numbers (`--foreground`) + electric blue signal (`--primary`): numbers read, blue directs.
- Structural light as ambient material: cold radial glow, not decorative neon.
- Sharp edges, deep negative space, engineered geometric type.
- Monochrome blue chart ramp: chart-1 through chart-5.
- One structural visual decision per viewport beyond color: crop, offset, scale, path, rail, field, light cone, or typographic lockup.

- **Don't** render focal numbers in `--primary` — digits use `--foreground`; `--primary` is signal accent only.
- **Don't** use warm tones, orange, or amber anywhere.
- **Don't** use heavy shadows, frosted glass, `backdrop-blur`, rim lighting, drop shadows as design features, card-edge glow, or text glow.
- **Don't** use large-radius cards, `rounded-xl`, `rounded-2xl`, `rounded-3xl`, blob cards, or soft tiles; cards and panels use `rounded-[0px]` through `rounded-[4px]`.
- **Don't** nest panels beyond one level or wrap multiple sections in page-level card containers.
- **Don't** use Inter, Geist Sans, Space Grotesk, or other overused Latin-only faces for body or labels; MiSans is primary, Satoshi and Geist Mono are Display Number only.
- **Don't** apply weight 600 globally; reserve it for indicator values and marker numbers. No `font-bold`, `font-extrabold`, `font-black`, or ≥700 on Display Number, titles, or large text.
- **Don't** use the same panel material for every section; vary material logic by archetype.
- **Don't** fade whole sections with opacity-only, repeat identical `y + opacity` reveals, or animate CSS layout properties (`width`, `height`, `padding`, `margin`, `top`, `left`, `right`, `bottom`, `font-size`, `gap`, `grid-template-*`). Animate `transform` and `opacity`; use FLIP only for unavoidable layout transitions.
- **Don't** tween numbers as a single value, expose rolling-number internals, or duplicate unit/percent signs; use per-digit spring and final static fallback.
- **Don't** use ease strings; cubic-bezier arrays only.
- **Don't** use `h-screen`; use `min-h-dvh`.
- **Don't** render any text below `text-[10px]`; required reading text uses `text-[14px]+` per §8.
- **Don't** wrap every number in `<AnimateNumber>`. Reserve it for **key numbers** — those that carry a section's claim or primary evidence. Labels, ordinals (rank 1/2/3), dates, axis values, footnote figures, and supporting sub-metrics render as plain text. If a section has more than 3 rolling numbers, split the claims across sub-sections.
- **Don't** use `useInView()` + conditional `animate={}` for entrance animations; use `whileInView` + `viewport`. `useInView` is only for pausing continuous motion such as shader speed or SVG loop playback.

## 10. Pattern Overview

### Scenario Mindset

This page is a story told in data, not a dashboard — every section is a chapter, every chart is evidence for a claim.
The narrative arc runs across the whole page: opening hook → supporting evidence → closing impact. Each section advances exactly one beat of the arc.
Each section carries one focal claim and exactly one supporting visual (chart, ranking, or quote). Parallel KPI tiles, side-by-side metric grids, and three competing focal numbers belong to a dashboard, not a campaign report.
A successful page lets the reader leave with three things: the headline number, the why behind it, the so-what of it.
Archetype names are internal planning labels only. Visible eyebrows, captions, and labels come from the topic, period, data role, or business meaning, not from section archetype names.

### Scope

Scope: scrollable single-page data narrative where numbers are the protagonist.

Atmosphere: Information density Low → High (rhythm-controlled) · Visual rhythm Strong alternation (different archetype per section) · Narrative arc Beginning → Middle → End.

Supported data shapes: time-series · proportions · paired metrics · ranking · grouped metrics · event sequence · peer catalog · comparison.

### Voice & Copy

The page's copy reads like a curator's wall text — terse, third-person, observational.

- Voice: third-person observational. Use `we` only in attribution; never address the reader as `you`.
- Statements, not calls to action: `Bookings closed at 142,300`, not `We booked 142,300!` — a campaign report is a read-only artifact.
- Eyebrows: uppercase, mono, `tracking-[0.14em]`. Titles: sentence case, no terminal period. Body: sentence case, full sentences, terminal punctuation.
- Numbers in copy: tabular figures, thousands separators, no decimal padding.
- Period strings use a `·` middle dot (U+00B7) with single spaces around it.

## 11. Section Archetype Library

A section is composed from three independent choices: an **archetype** (what the section says), a **composition treatment** (how it is laid out), and a **dominant move** (the element that leads the eye). Treatment selection follows the archetype's allowed list, item count, and §12 adjacency rules.

### 11.1 Composition Treatments

The layout-structure vocabulary. Specific spacing, radius, and color values come from the style layer.

| Treatment | Composition logic | Density |
|-----------|-------------------|---------|
| **Full-bleed Monolith** | One element fills the frame, vertically centered; supporting elements stack around it. | spacious |
| **Asymmetric Split** | Two unequal columns (roughly 3:2 or 2:1). One column leads; the other carries supporting evidence or annotation. | medium |
| **Stacked Band** | Full-width horizontal bands stacked vertically; each band is one sub-claim. | medium–dense |
| **Matrix Grid** | Equal-size cells in an N×M grid. Narratively bound — every cell is evidence for this section's single claim, not a free-standing tile stack. | dense |
| **Proportion Rail** | One continuous rail, band, or scale carrying a parts-of-whole reading. | medium |
| **Offset Frame** | Content disrupts the regular grid by one of: edge crop (cut at a frame side), off-center placement (sitting ~15-25% off the center axis), or overflow (extending past one frame edge). Pick exactly one disruption per section. | medium |
| **Sequence Track** | A linear stepped progression; each step is index → title → note. | medium–dense |
| **Typographic Field** | Composition built from type alone — scale, weight, and spacing do the work, with no panels, cards, or chrome. Focal element occupies 60-80% of viewport width; supporting elements (eyebrow, subtitle) sit at ≤ Section Tertiary scale and occupy ≤ 1/3 viewport height. | spacious–medium |
| **Annotation Rail** | A main element (3/4 width) paired with a narrow annotation rail (1/4 width) carrying notes or callouts. Annotations align to the main element's reading axis. | medium |

### 11.2 Dominant Move

Each section leads with exactly one dominant move. Moves are **steady** or **disruptive**; page-level disruptive budget is set in §12.

| Dominant Move | Class |
|---------------|-------|
| Scale jump — the focal element is ≥ 2 scale tiers larger than its surroundings | steady |
| Single stroke — one drawn line, accent stroke, or light cone leads the eye | steady |
| Path reveal — a curve draws in, or a proportion rail fills | steady |
| Crop / bleed — the focal element is cropped by an edge or overflows the frame | disruptive |
| Offset placement — the focal element sits deliberately off the regular grid position | disruptive |
| Column break — one element spans columns or goes full-width, interrupting the grid | disruptive |

### 11.3 Archetypes

Each archetype lists trigger, slots, allowed treatments with selection rule, and dominant-move options. Archetype names are internal planning labels; visible labels come from topic, period, data role, or business meaning.

**Hero Monolith** — Trigger: opening anchor metric. Slots: eyebrow · metric-label · primary-value · unit-text · delta-indicator · subtitle. Treatments: Full-bleed Monolith **(default)** · Offset Frame · Typographic Field. Dominant Move: scale jump · crop/bleed · single stroke.
**Time Series** — Trigger: ordered values over a time dimension. Slots: title · time-axis · value-axis · series (1–3) · callout. Treatments: Stacked Band **(default)** (chart over a callout band) · Asymmetric Split (chart leads, reading on the side) · Annotation Rail. Dominant Move: path reveal · scale jump on the peak point.
**Proportion Field** — Trigger: parts-of-whole as percentages. Slots: proportion-visual · focal-value · integrated labels (2–5) · note. Treatments: Proportion Rail **(default)** · Stacked Band · Typographic Field. Dominant Move: path reveal (rail fill) · scale jump. Donut, pie, and ring charts are not used — proportion reads as a continuous rail or band.
**Comparison** — Trigger: two metrics contrasted. Slots: left-value · left-label · right-value · right-label · divider · delta. Treatments: Asymmetric Split **(default)** (weighted toward the leading value) · Stacked Band (stacked contrast) · Offset Frame. Dominant Move: scale jump · offset placement.
**Ranking / List** — Trigger: items ordered by magnitude. Slots: rank · label · value · delta · highlight (top 1–3). Treatments: Stacked Band **(default)** (≤ 5 items) · Matrix Grid (≥ 6 items, truncated past a readable count) · Asymmetric Split (top-1 isolated, the rest compressed). Dominant Move: scale jump on top-1 · offset placement · single stroke as a magnitude scale.
**Grouped Metric Cluster** — Trigger: several parallel metrics that together evidence one claim — for example a scenario's sub-metrics. Slots: cluster-claim · metric cells (2–6, each: label · value · note). Treatments: Matrix Grid **(default)** · Stacked Band. Dominant Move: scale jump (one metric leads) · single stroke. The cluster is narratively bound — one claim's evidence, not a free-standing dashboard tile stack (see §16).
**Sequence / Timeline** — Trigger: time-ordered events, milestones, or a process — distinct from Time Series, which carries values, not events. Slots: track · steps (each: index · title · note) · terminus. Treatments: Sequence Track **(default)** · Stacked Band. Dominant Move: path reveal · single stroke.
**Peer Set / Catalog** — Trigger: a set of same-kind peers shown together without a magnitude order — a product family, a set of brands. Slots: set-label · peer cells (each: name · attribute · optional value). Treatments: Matrix Grid **(default)** · Stacked Band · Asymmetric Split (one peer featured). Dominant Move: scale jump on a featured peer · crop/bleed. Narratively bound, same as Grouped Metric Cluster.
**Quote Interstitial** — Trigger: a narrative pause between data sections. Slots: mark (lucide-react `<Quote />`, sized to text scale, color `var(--primary)`) · text · attribution. Treatments: Typographic Field **(default)** · Offset Frame. Dominant Move: column break · offset placement. Quote text is one sentence, 28 words or fewer.
**Outro Reverent** — Trigger: end of report. Slots: title · subtitle · flourish · statistical caveats (period, source, audit note where relevant). Treatments: Full-bleed Monolith **(default)** · Typographic Field. Dominant Move: single stroke · scale jump.

## 12. Composition

Default sequence: Hero Monolith → data-supported evidence chapters → optional Outro Reverent.

Section count follows data and story. Sparse datasets may produce Hero plus 1–2 evidence chapters. Stop before filler. Omit data-absent archetypes.

### 12.1 Rhythm discipline

Four countable self-check rules:

1. **Density rotation** — classify every section as `dense`, `medium`, or `spacious` by atomic-element count (dense ≥ 6, medium 3–5, spacious ≤ 2). Adjacent sections differ in density; no two consecutive `dense` sections; use all three tiers across the page.
2. **Treatment variety** — no two **consecutive** sections use the same composition treatment or archetype. Non-adjacent sections may share a treatment — for example, Hero Full-bleed Monolith at the top and Outro Full-bleed Monolith at the bottom is allowed and conventional.
3. **Bold-move budget** — each section leads with exactly one dominant move. Disruptive moves (crop/bleed, offset placement, column break) stay near one in five sections; the rest lead with a steady move. When section count < 5, allow up to 1 disruptive move per page; when ≥ 5, disruptive count ≤ ceil(section_count × 0.25).
4. **Break cadence** — at least one section per page breaks the grid: Full-bleed Monolith, Offset Frame, or Typographic Field. A page made only of regular grids and stacked bands reads as a template. A "break section" is any section whose treatment is Full-bleed Monolith, Offset Frame, or Typographic Field — treatments that interrupt the regular grid logic.

### 12.2 Other composition rules

Background rhythm varies through composition, linework, and light placement, not deep section bands.

Chapter markers: sequential 01, 02, 03… when useful. Markers are optional and vary by composition — side note, tick mark, rail label, divider number, or small stamp. **Don't** repeat the same circular stamp treatment across every chapter.

## 13. Section Anatomy

### 13.1 Hero Monolith

Focal: primary-value — the numeric value itself, rendered as the single largest Hero element at Display Number scale and animated with count-up roll. Secondary: delta-indicator, subtitle. Tertiary: eyebrow, metric-label, unit-text. Metric-label and unit-text never render at Display Number or Section scale and never exceed the primary-value.

Hero background field: full-bleed shader per style layer. The Hero background is shader only; no raster images or photographs unless explicitly requested.

Hero composition: the primary number interacts with at least one structural element from its treatment — cropped edge, spotlight cone, stage horizon, offset frame, or data path. Avoid the plain centered big-number Hero made only from eyebrow, number, badge, and paragraph.

Primary-value selection — pick exactly one numeric value to headline the report. Resolve by field-name pattern, stopping at the first match:

1. **Rate / percentage field** — a field whose display name contains a percent or rate indicator. Show the average across all records.
2. **Explicit aggregate field** — a field whose display name is an aggregate keyword (total, aggregate, 总计, 合计). Show its sum.
3. **Primary metric field (max)** — otherwise, identify the primary metric field by name semantics — the field most likely to headline a report (revenue, GMV, score). Show its maximum.
4. **Primary metric field (avg)** — same field as rule 3, show the average instead.

Display the selected value directly. Preserve units and percent signs already present in the source value. If the selected value is missing or null, omit the Hero Monolith section entirely.

Eyebrow slot format: `{topic} · {period}`. Emit the actual period from data context; if period is unavailable, omit the period segment — do not emit placeholder strings.

### Hero animation contract

Hero entrance uses parent `motion.div` with `animate` (not `whileInView`) to stagger eyebrow → primary-value → subtitle. AnimateNumber roll starts when its child value changes from 0 to target.

```tsx
const heroVariants = { hidden: {}, visible: { transition: { staggerChildren: 0.12 } } };
const fadeUp = { hidden: { opacity: 0, y: 16 }, visible: { opacity: 1, y: 0, transition: { duration: 0.7, ease: EASE.out } } };

<motion.div initial="hidden" animate="visible" variants={heroVariants}>
  <motion.p variants={fadeUp}>{eyebrow}</motion.p>
  <motion.div variants={fadeUp}>
    <AnimateNumber transition={{ type: "spring", duration: 2.0, bounce: 0 }}>{displayValue || 0}</AnimateNumber>
  </motion.div>
  <motion.p variants={fadeUp}>{subtitle}</motion.p>
</motion.div>
```

`displayValue` starts at `0` via `|| 0`, then updates to target after data loads; this 0→target change starts per-digit scroll. Hero uses `animate` because it is visible on load.

Hero adds a structural line that draws in alongside the number, so the figure does not sit alone on the background:

```tsx
<motion.svg className="absolute inset-x-0 bottom-[28%] pointer-events-none" viewBox="0 0 1440 4" preserveAspectRatio="none" aria-hidden>
  <motion.line
    x1="120" y1="2" x2="1320" y2="2"
    stroke="var(--primary)" strokeWidth="1"
    initial={{ pathLength: 0 }}
    animate={{ pathLength: 1 }}
    transition={{ duration: 2.2, ease: EASE.out, delay: 0.4 }}
  />
</motion.svg>
```

Variants: `<line>` for horizon, `<path d="M ... A ... ">` for a single corner arc, or vertical signal tick stack. Stroke is always `var(--primary)`, width 1, drawn at `delay: 0.4s` so it appears while the number rolls.

Hero exit transition: as the user scrolls past the first viewport, the Hero section fades and scales down to hand visual weight to the next chapter.

```tsx
const heroRef = useRef(null);
const prefersReducedMotion = useReducedMotion();
const { scrollYProgress } = useScroll({ target: heroRef, offset: ["start start", "end start"] });
const opacity = useTransform(scrollYProgress, [0, 1], [1, 0.4]);
const scale = useTransform(scrollYProgress, [0, 1], [1, 0.92]);

<motion.section
  ref={heroRef}
  style={prefersReducedMotion ? undefined : { opacity, scale }}
>
  {/* Hero content */}
</motion.section>
```

When `prefersReducedMotion` is true, the style transforms are skipped and the Hero remains static. This is the only place `useScroll` is permitted; do not use it elsewhere in the page.

## 15. Functional States

- **Loading**: skeleton replaces only data-dependent slots. Static section structure, Hero shader, and chapter markers remain visible.
- **Empty**: section frame + centered "No data available" in `--foreground-3`.
- **Error**: frame + retry icon + "Failed to load" + retry button in `--foreground-2`.

## 16. Do's and Don'ts

Do:
- Alternate archetypes between sections.
- Keep backgrounds near-black; vary rhythm through composition and linework.
- Use one focal element per section.
- Skip data-absent sections.
- Use chapter markers only where they support navigation or rhythm.
- Use visible labels from topic, period, metric role, or business meaning.

- **Don't** repeat the same archetype or composition treatment consecutively.
- **Don't** show archetype names such as `Grouped Metric Cluster`, `Proportion Field`, `Ranking / List`, or `Outro Reverent` in visible UI.
- **Don't** use equal 3-column grids, sidecar KPI tile stacks, page-wide parallel tile stacks, or a Matrix/Grid cluster that is not one claim's evidence.
- **Don't** use a plain centered big-number Hero with pill indicator as the whole composition; compose the number with crop, path, light, or stage structure.
- **Don't** fix section heights; let content determine height with min-height.
- **Don't** show multiple primary numbers in one section.
- **Don't** separate chart legends from their chart.
- **Don't** use donut, pie, or ring charts of any kind, or detached dot legends; proportion is a continuous rail or band, with segments tinted in chart-ramp order.
- **Don't** repeat identical circular chapter markers across all sections; vary or omit markers.
- **Don't** apply identical `y + opacity` section reveals everywhere or hide whole section wrappers before they enter view.
- **Don't** render white or light-colored overlays, masks, scrims, or loading skeletons; overlays and skeletons use dark surface or ink tokens.
- **Don't** show more than 5 ranking items without truncation.
- **Don't** allow horizontal scroll; stack on mobile.
- **Don't** use emoji anywhere — not in copy, labels, indicators, captions, or bullets.
- **Don't** add CTA buttons, action buttons, links styled as buttons, "view full data" / "view more" / "view detail" / "查看完整", dashboard verbs (track, monitor, drill down, explore), marketing verbs (unlock, discover, supercharge, transform), or second-person imperatives.
- **Don't** force an outro when the data has no closing claim; end on the strongest supported evidence section.
- **Don't** keep a whole page at `medium` density, build a page with zero break sections, give every section a heading, ship perfect symmetry with no visual tension, or lead a section with more than one dominant move.

**DeltaIndicator** — Compact change indicator with prominent directional arrow.
```tsx
function DeltaIndicator({ value, direction, label }: { value: string; direction: "up" | "down"; label?: string }) {
  const isUp = direction === "up";
  const Arrow = isUp ? "↑" : "↓";
  const tone = isUp
    ? { background: "oklch(0.620 0.180 var(--brand-hue) / 0.06)", border: "1px solid oklch(0.620 0.180 var(--brand-hue) / 0.45)", color: "var(--primary)" }
    : { background: "oklch(0.500 0.020 262 / 0.05)", border: "1px solid oklch(0.580 0.012 255 / 0.4)", color: "var(--foreground-2)" };
  return (
    <span className="inline-flex items-center gap-1.5 px-3 py-1.5 rounded-[4px] text-[14px] font-medium" style={tone}>
      <span className="text-[18px] font-semibold leading-none" aria-hidden>{Arrow}</span>
      <span className="font-semibold">{value}</span>
      {label ? <span className="opacity-70 font-normal">{label}</span> : null}
    </span>
  );
}
```

## 18. Component Constraints

Use top-level hooks, typed props, `motion/react`, `motion-plus/react`, numeric easing arrays, `aria-hidden` for decorative visuals, semantic labels for readable values, `isAnimationActive={false}` on Recharts, and reduced-motion fallbacks for AnimateNumber, WebGL, spotlight, and off-screen continuous motion.
